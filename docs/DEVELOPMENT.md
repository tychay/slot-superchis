# Development

Everything runs in the Docker build image (`docker/`), so a Mac or Linux box needs only Docker.
Clone with `--recursive` (or run `git submodule update --init`): the carousel's built-in art and the
label converter come from the pinned `vendor/slot-advance` submodule.

## Build

```sh
./build.sh          # superfw.gba (make BOARD=chis COMPRESSION_RATIO=10)
./build.sh clean
```

Passing any make variable replaces the defaults, so spell them out:
`./build.sh BOARD=chis COMPRESSION_RATIO=10 SLOT_DIAG=1` builds the diagnostic version.

- The build fails if `superfw.gba` grows beyond 2,048 KB (`SLOT_MAX_IMAGE_KB`).
- The version suffix on the Info tab is `SLOT_MILESTONE` at the top of the `Makefile`.
- The carousel is `slot.payload`, built from `src/slot/` and copied to SDRAM at boot. Its artwork
  is `res/slot_assets.pack`, compressed and unpacked at boot (ADR-0011).

## Hardware rules

SuperCard SDRAM is on the 16-bit cartridge bus. Both rules were found on hardware and neither shows
up in an emulator:

- **No byte stores into SDRAM.** An 8-bit write corrupts the neighbouring byte. Use 16/32-bit
  stores, or `slot_sdram_store()` for byte data.
- **No DMA with an SDRAM source.** It returns wrong data or hangs. Use `Slot_Copy`.

Details in [ADR-0010](../adr/0010-sdram-is-16-bit-write-only-payload-statics-in-iwram.md).

## Preview ROM

`./build.sh preview` builds `slot-preview.gba`: the carousel linked against a stub host
(`src/slot/preview_host.c`) with a made-up library instead of an SD card, so it runs in mGBA.
Select shows a stub "stock UI" screen and A shows a stub load screen; B returns from both.

Keys held at start pick the library:

| Held | Library |
|---|---|
| nothing | about 8 made-up titles per shelf, some with art |
| Up | 3,000-title stress shelf (long names, UTF-8, some too long to launch) |
| Down | every shelf empty |
| Left | no `Games` folder |

## Screenshot harness

`tools/preview_shots.sh <rom.gba> <sequence> [outdir]` runs a ROM headless in libmgba inside the
build container and writes PNGs to `build/shots/`.

```sh
./build.sh preview
tools/preview_shots.sh slot-preview.gba wait:150,shot:boot,Right,Right,wait:40,shot:right2,R,wait:40,shot:gb
tools/preview_shots.sh slot-preview.gba wait:150,B+Start,wait:40,shot:dark
```

Steps: `wait:N`, `KEY`, `KEY+KEY` (chord), `hold:KEY[:N]`, `shot[:NAME]`, `reg:ADDR`. Run it
without arguments for the full grammar.

## Unit tests

`./build.sh slot-tests` runs the host tests with AddressSanitizer:

- `tests/slot_scan_test.c`: filtering, sorting, 5,000-entry and 255-byte-name libraries.
- `tests/slot_settings_test.c`: `SETTINGS.TXT` round trip and validation.
- `tests/slot_bmp_test.c`: Cart Studio art, using converter output made in the container plus the
  made-up labels in `tests/fixtures/art` (generated by `tests/make_fixture_labels.py`).

Upstream SuperFW's own `tests/Makefile` is unchanged; it needs `lcov` and OpenSSL, which the
image does not install.
